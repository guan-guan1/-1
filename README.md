# 打卡

一个手机优先、可离线使用的打卡 MVP。未登录时记录保存在当前浏览器；登录后会将任务、打卡和备注同步到 Supabase 云端。

## 功能

- 首页显示当前选中的约束任务，默认是“晚上不点外卖”。
- 可以新建多个打卡任务，在首页任务栏中切换；每项任务拥有独立的打卡记录和月历。
- 新建或编辑任务时可以设置每日打卡时间段；跨午夜时段会把凌晨的记录归到前一天。
- 只有当前任务处于可打卡时间时才能记录当前打卡日；过去没有记录的日期可补录，已有历史记录只读。
- 按钮和日历单元格带有轻量点击反馈动效，并遵从系统的减少动态效果设置。
- 可以编辑当前任务名称和时间段。
- 可以删除当前任务；删除前会二次确认并同时移除该任务的本地打卡记录。至少保留一项任务。
- 每个任务的每个日期可以保存一条文字备注；选中该日期时，有备注才会显示，日历上也会有备注标记。清空内容并保存可删除备注。
- 为选中日期记录“今晚遵守了，完成打卡”或“嘴馋了，没忍住”。
- 小型月历显示当前任务的成功、失败和未记录日期；过去没有记录的日期可补录，已有记录不可修改。
- 在当前可打卡时间内把失败记录改为成功时，会先显示“你真的确定要改吗，你最好真的没点外卖”确认窗口。
- 原单任务版本的数据会在升级后迁移到默认任务中。
- 页面和图标等静态资源可缓存，安装后可离线打开。
- 可注册邮箱账号并登录；登录后首次会将本机已有数据导入云端，其他设备登录后可读取云端任务和记录。
- 打卡或备注变化后自动同步；重新打开页面、联网或切回页面时会拉取云端变化。账号数据按用户隔离。

## 配置 Supabase 云同步

1. 在 Supabase 项目的 **SQL Editor** 中运行 [`supabase/setup.sql`](supabase/setup.sql)。此脚本创建每个账号一行的 JSON 数据表，启用 RLS，并只允许登录用户读写自己的记录。
2. 确认 [`supabase-config.js`](supabase-config.js) 中的 Project URL 与 Publishable key 对应你的项目。Publishable key 本来就用于浏览器端；不要放入 `secret` 或 `service_role` key。
3. 在 Supabase **Authentication → URL Configuration** 中，把部署后的网站地址设为 Site URL，并将该地址及其子路径加入 Redirect URLs。GitHub Pages 项目站点通常是 `https://guan-guan1.github.io/-1/`；发布完成后以 GitHub Pages 页面显示的地址为准。
4. 在 GitHub 仓库 **Settings → Pages** 中把构建来源设为 **GitHub Actions**。推送到 `main` 后，工作流会发布静态网站。
5. 页面上线后，在应用内使用邮箱和至少 8 位密码注册。若 Supabase 要求邮件确认，先确认邮件，再回到应用登录。

首次登录时，若账号还没有云端数据，应用会上传当前设备的已有任务、打卡和备注。若账号已有云端数据，会合并本机独有日期与任务；同一任务同一天发生冲突时以云端记录为准，并在替换本机状态前保留一份本机存储备份。未登录时仍可在本机使用。离线更改会保留在本机，联网后再同步。

Supabase 项目地址和 Publishable key 会随静态网页公开，这是浏览器端的正常用法；安全性依赖 SQL 脚本中的 RLS 策略。不要向网页或仓库添加 Supabase Secret key、`service_role` key 或数据库密码。

## 在手机上安装

这是一个轻量 PWA。将整个文件夹部署到 HTTPS 静态网站后，用 Android 手机上的 Chrome 打开并选择“安装应用”或“添加到主屏幕”即可像应用一样启动。也可以先在电脑上用本地静态服务器预览，例如在此目录运行 `python -m http.server 8000`，再用浏览器打开 `http://localhost:8000`。

未登录时请在常用的同一浏览器和设备上使用；清除浏览器站点数据或更换浏览器会清除或无法看到本机打卡记录。应用不会自动读取支付记录。
